- 대상: `https://cjfwai-0128-be.vercel.app` (Vercel 프로덕션 배포, 커밋 `3efe03d` 이후)
- DB: Supabase Postgres (프로젝트 `oiyyfuwkmuhylhvkcebi`)
- 방식: 브라우저 없이 REST API를 직접 호출하는 API 레벨 E2E (스크립트: 세션 스크래치패드 `prod-e2e.js`)
- 참조 문서: `docs/3-user-scenario.md`
- 테스트 계정: `leader01`(팀장) / `member01`(팀원) — 프로덕션 DB에 이번 테스트를 위해 직접 시드
- 결과: **14건 중 실패 0건**

## 사전 이슈 및 수정 내역

첫 시도에서 `/api/auth/login`을 포함한 모든 DB 접근 요청이 응답 없이 멈췄다(Vercel Functions 대시보드에서 Timeout 33.3% 확인, Supabase 쪽엔 접속 시도 자체가 로그로 남지 않음). 원인은 Vercel 프로젝트의 `DATABASE_URL` 환경변수 값에 줄바꿈이 섞여 들어가 연결 문자열이 깨져 있었던 것 — 로컬 `.env.production`에서 동일한 증상을 먼저 발견해 고쳤던 것과 같은 문제였다. 사용자가 Vercel 대시보드에서 값을 정정하고 재배포한 뒤 정상화됨.

그 과정에서 코드 쪽에도 두 가지를 함께 고쳤다(이미 별도 커밋으로 반영됨):
- `pg.Pool`에 `ssl` 옵션 추가 (Supabase는 TLS 필수)
- 서버리스 엔트리에서 IPv4 DNS 해석 강제 + `connectionTimeoutMillis` 설정 (연결 실패 시 무한 대기 대신 명확히 실패하도록)

## DB 반영 확인

- `events`: 시나리오 1의 이벤트가 `종료` 상태로 정확히 전이, 시나리오 3(C6)의 이벤트도 수동 확정 후 `확정` 상태로 반영됨
- `restaurants`: 삼겹살천국의 `avg_satisfaction_score`가 리뷰 제출(5점) 반영 후 `5.00`으로 갱신, `last_visited_at`도 확정 시점 이벤트 날짜로 갱신됨 — F2→F1 피드백 루프(C5)가 실제 DB 레벨에서 정상 동작함을 확인

## 참고

이번 테스트는 배포된 백엔드 API만을 대상으로 했으며, 프론트엔드(Vercel에 별도 배포됐는지 여부)는 검증 범위에 포함하지 않았다. 테스트용으로 프로덕션 DB에 삽입한 계정(`leader01`, `member01`)과 식당 3건은 실제 운영 데이터가 아니므로, 운영 전 삭제 또는 실제 데이터로 교체가 필요하다.
