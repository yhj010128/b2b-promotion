# TeamBab 사용자 시나리오

| 버전 | 날짜       | 변경 내용 |
| ---- | ---------- | --------- |
| 1.0  | 2026-08-13 | 최초 작성 (PRD v1.1, 도메인 정의서 v1.3 기반) |

> 본 문서는 `2-PRD.md`의 F0~F2 기능, C1~C6 수용 기준을 근거로 팀장(총무)/팀원 2개 역할이 겪는 사용 흐름을 스텝별로 정리한다. Out-of-Scope(캘린더/Slack 연동, 알림, 팀 관리 등)는 다루지 않는다.

## 1. 정상 플로우 (Happy Path)

전제: 팀장과 팀원 모두 계정을 가지고 있다.

1. 팀장이 로그인한다. — F0 / C1
2. 팀장이 회식 일정(날짜/예산/인원)을 등록한다. — F1 부속 데이터
3. 팀원들이 로그인한다. — F0 / C1
4. 팀원들이 각자 희망 메뉴/식당, 못 먹는 음식을 선호 의견으로 제출한다. — F1
5. 팀장이 추천 결과 조회를 요청한다. 시스템은 예산 필터 + 선호 의견 + 식당별 누적 만족도(C5 가중치)를 반영해 추천 후보 목록을 계산해 응답한다. — F1 / C5
6. 팀장과 팀원이 추천 후보 목록을 확인한다. — F1
7. 팀장이 추천 후보 중 하나를 최종 확정한다. 회식 일정 상태가 "확정"으로 바뀐다. — F1 / C2(팀장만 가능)
8. 회식이 진행되고, 이후 팀장(또는 시스템)이 회식 상태를 "종료"로 변경한다.
9. 팀원들이 로그인 후 만족도 평가(별점 1~5 + 한줄평)를 입력한다. — F2 / C4
10. 시스템이 해당 식당의 누적 평균 만족도 점수를 갱신한다. — F2
11. 다음 회식 등록 시, 이 갱신된 점수가 5번 추천 로직의 가중치(C5)로 반영된다. — F2 → F1 피드백 루프

## 2. 예외 시나리오 1 — 예산 미입력 상태에서 추천 시도 (C3)

1. 팀장이 로그인한다. — F0
2. 팀장이 회식 일정을 등록하면서 예산을 입력하지 않는다.
3. 팀장(또는 팀원)이 추천 결과 조회를 요청한다.
4. 시스템은 예산 정보가 없음을 확인하고 추천을 실행하지 않은 채 "예산을 먼저 입력하세요" 오류를 반환한다. — F1 / C3
5. 팀장이 예산을 입력한 뒤 다시 추천을 요청하면 정상 플로우(1번 시나리오 5번 스텝)로 이어진다.

## 3. 예외 시나리오 2 — 추천 후보 0건일 때 팀장 수동 확정 (C6)

1. 팀장이 회식 일정과 예산을 등록한다.
2. 팀원들이 선호 의견을 제출한다.
3. 팀장이 추천 결과를 요청하나, 예산 조건을 만족하는 식당이 하나도 없다.
4. 시스템은 "조건에 맞는 추천 결과가 없습니다"를 표시한다. — F1 / C6
5. 팀장이 후보 목록 없이 식당을 직접 입력/선택해 수동으로 확정한다. — F1 / C6
6. 이후 흐름(회식 진행 → 종료 → 만족도 평가)은 정상 플로우 8~11번과 동일하게 이어진다.

## 4. 예외 시나리오 3 — 팀원의 확정 시도 (권한 오류, C2)

1. 팀원이 로그인한다. — F0
2. 팀원이 추천 결과를 조회한다.
3. 팀원이 (팀장 전용) 확정 API를 직접 호출한다.
4. 시스템은 403 권한 오류를 반환하고 확정을 거부한다. — F1 / C2
5. 팀원 화면에는 확정 버튼 자체가 노출되지 않으며, 확정은 팀장 로그인 후에만 가능하다.

## 5. 예외 시나리오 4 — 회식 종료 전 만족도 평가 시도 (C4)

1. 팀장이 추천 후보 중 하나를 확정한다. 회식 일정 상태는 "확정"이다 (아직 "종료" 아님).
2. 팀원이 로그인 후 만족도 평가를 입력하려 시도한다.
3. 시스템은 회식 상태가 "종료"가 아님을 확인하고 입력을 거부하며 "회식 종료 후 평가 가능"을 안내한다. — F2 / C4
4. 회식 상태가 "종료"로 바뀐 뒤 팀원이 다시 평가를 입력하면 정상 처리된다. — F2 / C4

## 6. 피드백 루프 시나리오 — 특정 식당의 만족도 저하가 다음 추천에 반영 (C5)

1. 1회차 회식: 팀장이 식당 A를 확정하고 회식을 진행한다.
2. 회식 종료 후 팀원들이 만족도 평가를 낮게(예: 평균 2점대) 입력한다. — F2
3. 시스템이 식당 A의 누적 평균 만족도 점수를 갱신하며, 이 값이 2.5점 미만이 된다. — F2
4. 2회차 회식: 팀장이 새 일정/예산을 등록하고, 팀원들이 선호 의견을 제출한다. 식당 A도 예산 조건은 만족한다.
5. 팀장이 추천 결과를 요청한다. 시스템은 식당 A의 누적 평균 만족도가 2.5점 미만이므로 식당 A를 후보에서 제외하지 않고 우선순위 최하위로 배치해 응답한다. — F1 / C5
6. (참고) 최근 3회 이내 방문 이력이 있는 식당도 동일하게 최하위로 배치된다. — C5
7. 팀장은 최하위로 밀린 식당 A 대신 다른 상위 후보를 확인하고 확정할 수 있다. — F1
