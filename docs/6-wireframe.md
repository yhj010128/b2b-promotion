# TeamBab 화면 와이어프레임

| 버전 | 날짜 | 변경 내용 |
|---|---|---|
| 1.0 | 2026-08-13 | 최초 작성 (도메인 정의서 v1.3, PRD v1.1, 사용자 시나리오, 프로젝트 구조 원칙, 아키텍처 다이어그램 기반) |

> 본 문서는 `4-project-principle.md`에 정의된 5개 화면(`LoginPage`, `EventFormPage`, `PreferenceFormPage`, `RecommendationPage`, `ReviewFormPage`)의 레이아웃을 텍스트 와이어프레임으로 정리한다. 디자인 시스템·컴포넌트 상세 스펙·브레이크포인트별 레이아웃은 5일/1인 개발 범위를 넘어서므로 다루지 않는다(오버엔지니어링 금지). 반응형 웹이므로 모바일에서는 아래 레이아웃이 세로로 쌓인다고 가정한다.

---

## 1. LoginPage — F0 (로그인)

**목적**: 팀장/팀원 공통 진입 화면. 인증 없이는 F1/F2 화면에 접근할 수 없다(C1). 인증되지 않은 사용자가 다른 화면에 접근을 시도하면 이 화면으로 리다이렉트된다.

```
+--------------------------------------+
|              TeamBab                 |
|                                       |
|   아이디  [_______________]          |
|   비밀번호[_______________]          |
|                                       |
|          [   로그인   ]               |
|                                       |
|   (오류 시) "아이디 또는 비밀번호가    |
|             올바르지 않습니다"        |
+--------------------------------------+
```

**UI 요소**
- 아이디/비밀번호 입력 필드 — 필수 입력
- 로그인 버튼 — 성공 시 access/refresh token 발급, 이전에 접근하려던 화면(또는 EventFormPage)으로 이동
- 오류 메시지 영역 — 인증 실패 시 표시. 미인증 상태로 다른 화면 접근 시에도 `ProtectedRoute`에 의해 이 화면으로 이동(C1)

---

## 2. EventFormPage — F1 부속 (회식 일정/예산 등록)

**목적**: 팀장(총무)이 회식 일정(날짜/예산/인원)을 등록한다. F1 추천이 동작하기 위한 최소 부속 데이터 입력 화면. 팀원은 조회만 가능(등록/수정 버튼 없음).

```
+--------------------------------------+
| TeamBab           [내 정보] [로그아웃] |
+--------------------------------------+
| 회식 일정 등록                        |
|                                       |
|  날짜        [__________]            |
|  1인당 예산  [__________] 원         |
|  인원        [__________] 명         |
|  상태        모집중                  |
|                                       |
|          [   등록/저장   ]            |
|                                       |
|  (팀원 조회 시) 등록/저장 버튼 없음,   |
|  읽기 전용으로 날짜/예산/인원 표시     |
+--------------------------------------+
```

**UI 요소**
- 날짜/인원 입력 — 필수
- 예산 입력 — 비워둔 채 저장 가능. 단, 예산 미입력 상태로 추천을 요청하면 RecommendationPage에서 C3 오류가 발생함을 이 화면 하단에 안내 문구로 짧게 표기
- 등록/저장 버튼 — 팀장만 노출(팀원은 읽기 전용 뷰)
- 상태 표시 — `모집중/확정/종료` (도메인 정의서 상태값 그대로 표시)

---

## 3. PreferenceFormPage — F1 (선호 의견 제출)

**목적**: 팀원이 희망 메뉴/식당, 못 먹는 음식을 제출한다.

```
+--------------------------------------+
| TeamBab           [내 정보] [로그아웃] |
+--------------------------------------+
| 선호 의견 제출 - 2026-08-20 회식      |
|                                       |
|  희망 메뉴/식당                       |
|  [____________________________]      |
|                                       |
|  못 먹는 음식/알레르기                |
|  [____________________________]      |
|                                       |
|          [   제출   ]                 |
|                                       |
|  제출 완료 시: "제출되었습니다"       |
+--------------------------------------+
```

**UI 요소**
- 희망 메뉴/식당 입력 — 선택 입력(자유 텍스트)
- 못 먹는 음식/알레르기 입력 — 선택 입력(자유 텍스트)
- 제출 버튼 — 팀원/팀장 모두 자신의 의견 제출 가능(팀장도 팀원처럼 의견을 낼 수 있음, 확정 권한만 팀장 전용)

---

## 4. RecommendationPage — F1 (추천 결과 조회/확정)

**목적**: 예산·선호 의견·식당별 누적 만족도(C5)를 반영한 추천 후보를 조회하고, 팀장이 그중 하나를 확정한다. 팀장/팀원 화면이 확정 버튼 유무로 다르다(C2).

### 4-1. 정상 상태 — 팀장 화면

```
+--------------------------------------+
| TeamBab           [내 정보] [로그아웃] |
+--------------------------------------+
| 추천 결과 - 2026-08-20 회식            |
|                                       |
|  +-----------------+ +-------------+ |
|  | 식당 A          | | 식당 B      | |
|  | 예상 1인 3만원   | | 예상 1인 2.8만원| |
|  | 만족도 ★★★★☆   | | 만족도 ★★★☆☆| |
|  |     [확정]      | |   [확정]    | |
|  +-----------------+ +-------------+ |
|  (누적 만족도 2.5 미만/최근 3회 방문  |
|   식당은 목록 하단에 낮은 순위로 표시)|
+--------------------------------------+
```

### 4-2. 정상 상태 — 팀원 화면

```
+--------------------------------------+
| TeamBab           [내 정보] [로그아웃] |
+--------------------------------------+
| 추천 결과 - 2026-08-20 회식            |
|                                       |
|  +-----------------+ +-------------+ |
|  | 식당 A          | | 식당 B      | |
|  | 예상 1인 3만원   | | 예상 1인 2.8만원| |
|  | 만족도 ★★★★☆   | | 만족도 ★★★☆☆| |
|  +-----------------+ +-------------+ |
|         (확정 버튼 없음)              |
+--------------------------------------+
```

### 4-3. 예외 — 예산 미입력 (C3)

```
+--------------------------------------+
| 추천 결과 - 2026-08-20 회식            |
|                                       |
|   "예산을 먼저 입력하세요"            |
|   [ 예산 입력하러 가기 ]  (팀장만)     |
+--------------------------------------+
```

### 4-4. 예외 — 추천 후보 0건 (C6, 팀장 화면)

```
+--------------------------------------+
| 추천 결과 - 2026-08-20 회식            |
|                                       |
|   "조건에 맞는 추천 결과가 없습니다"  |
|                                       |
|   수동 확정: 식당명 [____________]   |
|              [   확정   ]             |
+--------------------------------------+
```

**UI 요소**
- 후보 카드(`RestaurantCard`) — 식당명, 1인 예상 비용, 누적 만족도 별점 표시. C5에 따라 최하위 후보는 목록 정렬 순서로만 구분(제외 아님)
- 확정 버튼 — 팀장 화면에만 노출. 팀원 화면에는 렌더링 자체를 하지 않음(C2, API 직접 호출 시 403은 백엔드가 처리)
- 예산 미입력 안내 문구/이동 버튼 — C3
- 0건 안내 문구 + 수동 확정 입력 필드 — C6, 팀장 전용

## 5. ReviewFormPage — F2 (만족도 평가 입력)

**목적**: 회식 종료 후 팀원이 별점(1~5) + 한줄평을 입력한다. 회식 상태가 "종료"가 아니면 입력이 거부된다(C4).

### 5-1. 정상 상태 (회식 상태 = 종료)

```
+--------------------------------------+
| TeamBab           [내 정보] [로그아웃] |
+--------------------------------------+
| 만족도 평가 - 식당 A (2026-08-20)      |
|                                       |
|  별점   ☆ ☆ ☆ ☆ ☆  (StarRating)   |
|  한줄평 [____________________________]|
|                                       |
|          [   제출   ]                 |
+--------------------------------------+
```

### 5-2. 예외 — 회식 종료 전 (C4)

```
+--------------------------------------+
| 만족도 평가 - 식당 A (2026-08-20)      |
|                                       |
|   "회식 종료 후 평가 가능"            |
|   (별점/한줄평 입력, 제출 버튼 비활성)|
+--------------------------------------+
```

**UI 요소**
- 별점 입력(`StarRating`, 1~5) — 필수
- 한줄평 입력 — 선택 입력
- 제출 버튼 — 회식 상태가 "종료"일 때만 활성화. "확정" 등 종료 이전 상태면 비활성 + C4 안내 문구 표시
